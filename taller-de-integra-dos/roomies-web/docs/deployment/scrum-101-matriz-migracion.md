# SCRUM-101 · Matriz de migración a PostgreSQL Kubero TEST

Planificación sobre `136986e`, rama `SCRUM-101-migracion-postgresql-kubero`. Destino propuesto para el ensayo: PostgreSQL 17.6 con `private-v1`. Estado de las fases: pendientes de ejecución.

## Evidencia y convenciones

- **Contrato de código** identifica la tabla que consulta el repositorio o crea el DDL versionado. **Origen propuesto** identifica qué buscar en un inventario autorizado. En todas las filas quedan pendientes la base física autoritativa, la existencia y población de la tabla, el propietario y la versión efectiva del DDL. La aplicación de SCRUM-111 en Supabase consta como antecedente documental y requiere reconciliación con el inventario actual. [Evidencia SCRUM-111, l. 16](../SCRUM-111-perfil-final.md#L16)
- El selector de código admite `private-v1` por defecto y `haycupo-v1`. Compose Supabase selecciona `haycupo-v1` por defecto. Compose local usa PostgreSQL 18 y un bootstrap de prueba. [Selector, l. 8](../../backend/service_runtime/settings.py#L8) · [Compose Supabase, l. 6](../../docker-compose.supabase.yml#L6) · [Compose local, ll. 12–28](../../docker-compose.local.yml#L12)
- SCRUM-100 documenta PostgreSQL 17.6 en `roomies-db-test2`, DNS privado `roomies-db-test2-postgres:5432`, conexión desde Match, respaldo y recuperación de una sonda y una excepción TEST sin TLS. El ensayo de SCRUM-101 requiere un destino aislado y una autorización que cubra el uso de un eventual respaldo histórico. [Evidencia de Kubero, ll. 169–174](kubero.md#L169) · [Criterios de cierre, ll. 206–225](kubero.md#L206)
- Las abreviaturas de esquema en la matriz son **A** = `auth_users`, **L** = `listado_applications`, **M** = `match_conexion`, **C** = `convivencia_mensajeria` y **R** = `reportes`. «Mismo nombre» indica el esquema y tabla exactos de la columna de destino. PK indica clave primaria, FK indica restricción SQL documentada y referencia lógica indica una relación que se comprueba durante la conciliación. Los números ordenan la carga de filas. Los dependientes de una misma etapa pueden cargarse en paralelo si todas sus referencias están resueltas.
- Cada tabla cargada requiere conteo y huella sobre su proyección normalizada. La última columna añade el control específico que debe acompañar esa comparación.

### Punto de revisión para Auth/Users

El arranque versionado monta las rutas ampliadas cuando se cumple `ROOMIES_LOCAL_MODE=1` o se declara modo `supabase`. La otra rama registra las rutas de perfil, cuyo proveedor instancia `PostgresProfileRepository` a partir de `PostgresDatabaseSettings`. Esa configuración aplica una lista propia de parámetros y modos SSL para staging que excluye `sslmode=disable`. El runtime compartido usado por `PostgresUsers` tiene una excepción TEST separada. La incompatibilidad es posible si la revisión y configuración desplegadas seleccionan la ruta de perfil con ese validador de staging y el DSN de excepción. Para SCRUM-102 queda verificar la revisión, el modo efectivo, las rutas montadas y el adaptador por endpoint en Kubero, con evidencia sanitizada. ## Decisiones bloqueantes

1. **Origen y alcance.** Confirmar base autoritativa, versión de esquema, población y responsable por dominio, incluidos históricos, variantes legadas y archivos. Acordar qué consumidores permanecen activos durante el corte.
2. **Identidad y excepciones.** Confirmar autoridad Supabase y método de conciliación de UUID/ID. Acordar destino de usuarios sin vínculo, duplicados, huérfanos y autenticación legada antes de implementar la carga.
3. **DDL y contrato.** Aprobar `private-v1`, revisión por servicio, DDL base, orden de ampliaciones, seed CUT, conversiones CLP y timestamps, tratamiento de ocupación, histórico de aceptaciones y membresías. Definir cuándo copiar o reconstruir cada proyección derivada.
4. **Infraestructura y permisos.** Confirmar recurso aislado, capacidad, roles, owners, RLS de Convivencia, retención, responsables y alcance de la excepción TLS, especialmente para datos históricos. Coordinar con SCRUM-100.
5. **Activación y archivos.** Acordar con SCRUM-102 adaptador efectivo de Auth, revisión y configuración del Gateway y servicios, conectividad y almacenamiento durable. Acordar con SCRUM-103 credenciales internas, orden de reanudación y política de reintentos, drenaje e idempotencia.
6. **Corte y recuperación.** Definir ventana, responsables de decisión, tiempo y pérdida tolerables, estrategia de congelamiento o delta, criterios de avance y reversión y cuándo SCRUM-104 puede consumir la evidencia integrada.

**Primera acción segura.** Revisar esta matriz con custodios de datos e infraestructura usando el contrato versionado. Asignar responsable y evidencia requerida a cada origen pendiente, confirmar el mapa de identidad y elegir el recurso aislado para el ensayo sintético.
